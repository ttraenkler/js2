## Strongest candidate: Boolean seeds a public non-writable tag

Frozen source facts:

1. `src/codegen/array-object-proto.ts:2596` defines `makeGlue(ctx, brand, name, members, symbolTag?)`. Its optional fifth argument is copied directly into the public glue's `symbolTag` property at line 2607.
2. `ensureBooleanNativeProtoGlue` at lines 2966–2970 calls `makeGlue(ctx, brand, "Boolean", BOOLEAN_PROTO_METHODS, "Boolean")`. The adjacent Number and String registrations omit that fifth argument. `ensureSymbolNativeProtoGlue` at lines 3184–3191 intentionally supplies `"Symbol"`.
3. `src/codegen/native-proto.ts:855–868` materializes `glue.symbolTag` as a companion data property keyed by `__box_symbol(4)`, with `PROTOTYPE_SEED_FLAGS.symbolTag`.
4. `src/runtime/wasmgc/values/prototype-seeder-bodies.ts:5–8` defines that flag word as `0xbc`. The seeder explicitly documents the descriptor as writable false, enumerable false, configurable true. This is a JavaScript-visible own symbol property, not private builtin classification state.
5. Boolean builtin classification exists independently: `NATIVE_PROTO_BRAND_TAGS` in `object-proto-tostring.ts:137–140` includes Boolean; its primitive predicates include `__typeof_boolean`; wrapper-slot and `WrapperBoolean` carrier classifications also exist. Removing an erroneous public seed must preserve these builtin classifications.

Required semantics: a pristine Boolean.prototype has Boolean internal data and therefore the builtin tag Boolean, but does not acquire an own Symbol.toStringTag property merely from that brand. Number.prototype and String.prototype likewise need no own tag to classify correctly. Symbol.prototype does require its own configurable, non-writable `"Symbol"` tag. The original's ordinary Boolean assignment must create an own writable/enumerable/configurable tag and override both the prototype and primitive rendering. Do not make all builtin tags writable or remove Symbol's required seed.

Candidate causal chain: materializing Boolean.prototype can seed a non-writable `"Boolean"` entry; a later ordinary assignment can consequently be refused; the real tag lookup then returns `"Boolean"`. This is a concrete source candidate, NOT a demonstrated route for the recorded failing original. In a correctly routed strict assignment, a non-writable seed should cause TypeError before the assertion; the reported SameValue failure therefore cannot prove both variants executed or that this is the only defect. Obtain variant receipts and emitted-route evidence before attribution.

The narrow proposed production edit, if confirmed, is to omit only the fifth `"Boolean"` argument in `ensureBooleanNativeProtoGlue`, with an explanatory comment distinguishing builtin classification from public tag ownership. Do not change common descriptor flags, symbol IDs, carrier layouts, the generic setter, or the classifier to compensate.
